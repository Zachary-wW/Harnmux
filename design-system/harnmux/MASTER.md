# Harnmux — macOS 设计规范

状态：2026-10-21 SwiftUI 实现基线。原生源码已编译；静态预览与真实交互验收分开记录，见 feature verification.md。

## 目标与技术选择

用户在原生 harness 中安排工作，状态栏只负责进展、审批和交付。打开后首先回答：谁在执行、哪里需要我、结果在哪里。

采用 SwiftUI + 必要的 AppKit，依据是首版 macOS 状态栏场景。无需另一个聊天窗口或网页渲染引擎。

已运行用户指定的 ui-ux-pro-max：`--design-system`、`--stack swiftui` 和 `--domain ux`。原始生成结果见 `docs/ui-research/skill-generated-baseline.md`，仅供追踪，不具有规范效力。

保留：语义颜色、一致间距、明确的加载/错误、键盘、VoiceOver、Reduce Motion。舍弃：营销页 Hero/CTA、Lora/Raleway 字体、CSS/GSAP、移动断点、把所有 Mac 控件机械扩大到 44pt。Apple HIG 优先于通用数据库。

## 信息架构

1. 状态栏：单色 SF Symbol + 简短计数，待处理事项优先；不显示滚动文字或虚构进度百分比。
2. 弹层顶部：名称、连接状态、运行中和待处理数量；当前运行明确区分交流入口与 Leader（例如“入口 DSH · 负责人 Codex”）。建议宽 400pt，最高约 600pt，随屏幕空间调整。
3. 需要处理：审批、执行中断、连接错误，优先于普通任务。审批详情包含 harness、工具、目录、命令/变更、授权范围及信息完整性。
4. 活动任务：名称、角色、harness、模型、最近事件和经过时间。稳定排序，焦点所在行不因事件更新跳动。
5. 最近完成：摘要、验证情况与“查看交付”。执行结束标记“待验收”，明确区分 Leader 建议与用户对指定快照的验收；验收不自动合入。
6. 详情：模型报告、验收标准、固定快照、两类审查意见、差异、原生观察、worktree、继续/取消；原生会话跳转按能力开放。长日志按需展开。
7. 页脚：服务状态与设置；关闭弹层不停止任务。

HIG 一般推荐标准菜单；任务状态与长审批内容属于较复杂场景，故提议 `MenuBarExtra` 的 `.window` 样式。若实测能用标准菜单清晰表达，应继续简化。系统可能隐藏状态栏项，所以 CLI/当前 harness 查询始终可用，通知只用于有意义的完成、失败或待处理事项。

## 视觉语言

| 项目 | 规范 |
| --- | --- |
| 气质 | 安静、清晰、原生；用排版和对齐建立层级 |
| 字体 | 系统 SF；正文约 13pt，辅助约 12pt，标题约 16pt；尊重系统辅助设置 |
| 技术文本 | 仅命令/路径/标识符用等宽字体；数字和时长用等宽数字 |
| 间距 | 4/8/12/16/24pt；外边距 16pt，行内 8pt；避免多层卡片 |
| 颜色 | 系统 primary/secondary/accent 和语义状态色；明暗分别验证 |
| 主操作 | 单一突出操作；审批不设置回车默认授权或预选放行 |
| 图标 | SF Symbols；状态同时有文字，不使用 emoji 或拼造品牌标志 |
| 表面 | 系统窗口/材料、细分隔线和必要阴影；不堆叠装饰性玻璃效果 |
| 动效 | 约 150–200ms 的状态过渡；遵循 Reduce Motion；使用系统加载反馈 |

正式实现用动态语义色；静态预览的固定色只用于审查布局与明暗配对，不冒充系统材料的实际渲染结果。

## 交互与真实性

- 状态覆盖排队、准备目录、执行中、等待审批、取消中、已取消、待验收、失败、中断/未知。
- 没有原生进度就显示最近事件和时长，不根据 token/耗时推算百分比。
- 请求取消先进入取消中，收到终止证据后才显示已取消。
- 审批使用“允许一次”“拒绝”；过期/断开时禁用，信息不足时明确提示，不能隐藏工具参数。
- 不支持的跳转/自动唤醒给出原因与查询路径，不呈现成已可用按钮。
- 任务详情分别展示角色、harness、请求/实际模型和 原生会话标识（若已创建），不能只显示模型名而隐藏实际执行框架。
- 执行完成不等于验收、测试全部通过或已合并；服务连接状态也与任务结果分开。
- 通知去重，不展示完整命令、凭据、代码或敏感路径，不逐 token 刷屏。
- 视图的 `.task` 只拥有订阅读取，不拥有 worker；UI 关闭或被系统终止不应取消执行。
- “退出界面”和“停止服务”分开。断开后保留上次数据并标记过期。

## 验收门槛

- 明暗分别检查：正文和小字至少 4.5:1，大字/关键非文字控件至少 3:1；半透明背景须实际测量。
- Tab/Shift-Tab、方向键、Escape、复制结果、可见焦点、VoiceOver 可用；Enter 不误触授权。
- 验证放大文字、长中文/英文、长路径、多条审批、空状态、离线、重启；不得溢出或遮挡操作。
- 状态不只依赖颜色，列表不随事件跳动，播报节流；动画尊重减少动态效果。
- 静态截图、原生运行、交互可访问性、协议闭环分别记录证据，截图不能证明任务执行已实现。

## 一手参考

- [Apple MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)：数据密集型 window、LSUIElement、移除状态栏项时的生命周期。
- [MenuBarExtraStyle.window](https://developer.apple.com/documentation/swiftui/menubarextrastyle/window)：类弹层窗口与原生控件。
- [Apple HIG — The menu bar](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar)：符号、可见性限制和优先使用菜单。

验收操作要求用户填写意见，明确引用回合与摘要；不设置默认键盘授权。快照缺失、连接失效或正在封存时禁用。模型自述始终标注来源，静态预览不替代运行验收。
